# MP3 Converter — mp3convert.tools

Free online MP3 tools built with Next.js (App Router). All audio is processed **inside the visitor's browser** —
files are never uploaded to a server.

## Tools
| Route | Tool |
| --- | --- |
| `/` | MP3 converter for any audio/video file, paste-a-link downloader and voice recorder |
| `/youtube-to-mp3`, `/youtube-to-mp4`, `/online-video-downloader` | Paste a link → download MP4 or convert to MP3 (needs the download service) |
| `/mp4-to-mp3`, `/video-to-mp3`, `/wav-to-mp3`, `/m4a-to-mp3`, `/flac-to-mp3`, `/aac-to-mp3`, `/ogg-to-mp3`, `/opus-to-mp3`, `/webm-to-mp3`, `/mov-to-mp3`, `/mkv-to-mp3`, `/podcast-to-mp3` | Format-specific converter pages |
| `/voice-to-mp3` | Microphone recorder → MP3 |
| `/mp3-cutter` | Waveform trimmer: keep/remove selection, fade in/out, preview |
| `/mp3-compressor` | Re-encode at 32–160 kbps, shows size saved |
| `/audio-joiner` | Merge files in any order with optional gaps |
| `/about`, `/contact`, `/privacy-policy`, `/terms`, `/copyright` | Info and legal pages |

## How it works (`lib/audio-engine.js`)
1. **Decode** with the browser's Web Audio API (fast path).
2. If the browser can't read the file (e.g. MKV/AC3, AVI, WMA, MP4 in some browsers), **fall back to FFmpeg**
   compiled to WebAssembly (`public/ffmpeg-worker.js` + `@ffmpeg/core`). The ~32 MB core is downloaded only when needed.
3. **Encode** MP3 with LAME ([lamejs](https://github.com/zhuker/lamejs), LGPL-3.0) in a Web Worker (`public/mp3-worker.js`).

Files are processed one at a time to keep memory use low; the limit is 500 MB per file.

## Link downloads (separate server)
Browsers cannot fetch videos from other websites, so link downloads use a small service in
[`downloader/`](downloader/README.md) (Node + yt-dlp + FFmpeg, Docker, automatic HTTPS with Caddy).
Run it on a VPS, then set this environment variable in Vercel and redeploy:

```
NEXT_PUBLIC_DOWNLOADER_URL=https://dl.mp3convert.tools
```
Without it, the "Paste Link" tools show a friendly "not set up yet" message and everything else keeps working.

## Testimonials (visitor reviews)
The homepage "Testimonials" section lets visitors post a star rating, review and optional photo. Reviews are stored
in Upstash Redis (`lib/reviews-store.js`, API in `app/api/reviews/`). Email addresses are never shown publicly.

| Variable | Purpose |
| --- | --- |
| `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` (or `KV_REST_API_URL`, `KV_REST_API_TOKEN`) | Storage. Added automatically when you connect Upstash Redis in Vercel → Storage. |
| `REVIEWS_ADMIN_KEY` | Password (12+ characters) for the moderation page at `/admin/reviews`. |
| `RESEND_API_KEY`, `REVIEWS_FROM_EMAIL` | Optional. Sends a confirmation link; confirmed reviews get the **Verified** badge. |
| `REVIEWS_AUTO_APPROVE=1` | Optional. Publish without manual approval (after email confirmation when enabled). |
| `REVIEWS_SITE_URL` | Optional. Base URL used in confirmation links (defaults to the request's own URL). |

Without the storage variables the section shows "Reviews open soon" and the rest of the site works normally.

## Development
```bash
npm install     # also copies the FFmpeg core into public/ffmpeg (postinstall)
npm run dev     # http://localhost:3000
npm run build && npm start
```
`public/ffmpeg/` is generated by `scripts/copy-ffmpeg.mjs` and is not committed. Hosts that run `npm install`
(Vercel, Netlify, etc.) create it automatically.
